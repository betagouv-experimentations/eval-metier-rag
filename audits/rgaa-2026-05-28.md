## Non-conformités détectées et corrigées

Les 3 NCs identifiées ont été **corrigées pendant l'audit**.

### ✅ [NC → CORRIGÉ] 9.1 — Hiérarchie des titres : h1 manquant sur la page annotation question

- **Élément concerné :** `src/components/annotation/QuestionAnnotationView.tsx`
- **Problème :** La page `/annotation/[token]/[questionId]` n'avait aucun `<h1>` dans le
  contenu principal. Le composant `QuestionAnnotationView` commençait par un `<h2>` ("Votre
  évaluation") sans h1 précédent.
- **Correction :** La mention "Question" au-dessus du texte de la question a été convertie en
  `<h1 className="fr-h6">Question {position}</h1>`. La hiérarchie est désormais :
  h1 → h2 (Votre évaluation) → h3 (Sources A/B).
- **Priorité :** 🟠 Majeur → corrigé

### ✅ [NC → CORRIGÉ] 8.6 — Titres de pages incomplets

- **Éléments concernés :** `src/app/accessibilite/page.tsx` et `src/app/mentions-legales/page.tsx`
- **Problème :** Les titres étaient respectivement "Déclaration d'accessibilité" et
  "Mentions légales" — sans inclure le nom du site.
- **Correction :** Mis à jour en "Déclaration d'accessibilité — Éval Métier RAG" et
  "Mentions légales — Éval Métier RAG".
- **Priorité :** 🟡 Mineur → corrigé

### ✅ [NC → CORRIGÉ] 13.2 — Liens s'ouvrant dans un nouvel onglet sans indication

- **Éléments concernés :** 5 occurrences de liens source dans
  `src/components/annotation/QuestionAnnotationView.tsx` (×3) et
  `src/components/annotation/AnnotationForm.tsx` (×2) — tous avec `target="_blank"`.
- **Problème :** Les liens vers les sources (documents PDF / URLs) s'ouvraient dans un
  nouvel onglet sans aucune indication à l'utilisateur (ni texte, ni icône, ni `title`).
- **Correction :** Attribut `title={`${src} (nouvelle fenêtre)`}` ajouté sur chaque lien.
- **Priorité :** 🟡 Mineur → corrigé

## Critères conformes (sélection des points notables)

**Thème 1 — Images :**
- 1.2 C : Icônes DSFR (CSS classes + `<span aria-hidden="true">`) — toutes les icônes décoratives masquées correctement.

**Thème 3 — Couleurs :**
- 3.1 C : Information non transmise uniquement par la couleur (StatCard : couleur + libellé textuel).
- 3.2 C : Palette DSFR utilisée exclusivement — ratios conformes WCAG 2.1 AA (4.5:1 texte, 3:1 grands textes). Les quelques couleurs personnalisées (`#f5f5fe`, `#b8fec9`, `#ffe9a0`) utilisent du texte foncé standard, ratios ≥ 4.5:1 vérifiés.
- 3.3 C : Bordures personnalisées (`#6a6af4`, `#000091`) ≥ 3:1 sur fonds clairs.

**Thème 7 — Scripts :**
- 7.1 C : Composants DSFR (RadioButtons, Tabs, Accordion, Display) exposent correctement les rôles ARIA.
- 7.2 C : Rendu serveur Next.js (App Router, Server Components) — contenu accessible sans JS.
- 7.5 C : Messages de statut (succès/erreur enregistrement annotation) avec `aria-live="polite"` et `role="alert"`.

**Thème 8 — Éléments obligatoires :**
- 8.3 C : `<html lang="fr">` via `getHtmlAttributes({ lang: "fr" })` dans `layout.tsx`.
- 8.5-8.6 C : Chaque page a un `<title>` distinct et descriptif (format "Page — Éval Métier RAG") via `generateMetadata` ou `export const metadata`.

**Thème 9 — Structuration :**
- 9.1 C : Hiérarchie h1→h2→h3 respectée sur toutes les pages après correction.
- 9.2 C : Landmarks HTML5 : `<header>` (DSFR Header), `<nav aria-label="Menu principal">` (DSFR), `<main id="content" role="main">`, `<footer>` (DSFR Footer).

**Thème 10 — Présentation :**
- 10.7 C : Focus visible géré par DSFR — aucun `outline: none` dans le code.
- 10.8 C : Icônes décoratives : `aria-hidden="true"` systématique.

**Thème 11 — Formulaires :**
- 11.1 C : Tous les champs ont un label via composants DSFR (Upload `label`, Input `label`, RadioButtons `legend`).
- 11.5-7 C : RadioButtons DSFR rend `<fieldset>/<legend>` nativement.
- 11.9 C : Boutons descriptifs ("Importer et créer la campagne", "Enregistrer").
- 11.10 C : Champ fichier marqué `required: true`, erreur liée via `aria-describedby="upload-error"`.

**Thème 12 — Navigation :**
- 12.1 C : Deux systèmes sur toutes les pages — menu principal (DSFR Header) + fil d'Ariane (DSFR Breadcrumb).
- 12.7 C : Lien d'évitement `<a className="fr-skiplink" href="#content">Aller au contenu</a>` → `<main id="content">`.

## Résumé exécutif

L'application utilise le Design System de l'État (DSFR v1.x via `@codegouvfr/react-dsfr`)
qui gère nativement la grande majorité des critères RGAA (focus, couleurs, labels de
formulaires, landmarks, responsivité). Trois non-conformités mineures ont été identifiées
et corrigées pendant l'audit :

1. Un `<h1>` manquant sur la vue annotation individuelle (🟠 Majeur → corrigé)
2. Deux titres de pages sans nom du site (🟡 Mineur → corrigé)
3. Cinq liens vers des sources externes sans indication "nouvelle fenêtre" (🟡 Mineur → corrigé)

**Résultat après corrections : 0 non-conformité — 66/69 critères applicables conformes.**

La déclaration d'accessibilité `/accessibilite` est à mettre à jour avec ce résultat
avant la mise en production.
